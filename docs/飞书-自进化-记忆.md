# 飞书、自进化、记忆

这是一个可扩展的本机教育助手工作台，当前只完整落地了**申学**方向；“本地助手”是通用文件与研究能力，不是第二个教育方向。这里的三块分工不同：**飞书**是聊天通道，**记忆**让助手跨对话记得你，**自进化**把反复用过的做法收成可开关的能力。网页和飞书共用同一份数据，不是两套人设。

开始前请先 `pnpm dev`，打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)，选好 **申学助手** 或 **本地助手**。飞书还需要本机进程一直开着。

---

## 飞书

### 它是什么

把同一个助手接到飞书里。私聊直接说话；群里要 **@机器人**。回答会以一张会更新的卡片出现：先思考，再干活，最后成稿。需要你拍板时弹出选项按钮，不必打字回答。

它不是另一个助手。飞书里说「记住我本科清华」，网页上同一助手下一轮也能用到。

### 第一次怎么用

1. 按 [飞书机器人本地接入](./FEISHU_SETUP.md) 建好企业自建应用、开机器人、勾权限、用**长连接**订阅 `im.message.receive_v1`，回调里加上 `card.action.trigger`。
2. 网页右上角 **个人工作区 → 飞书**：填 App ID、App Secret、你的 Open ID，点 **保存并连接**。状态变成「长连接已建立」。也可以写在 `.env` 里；网页里保存过的配置会盖过 `.env`。
3. 终端出现 `Feishu long connection is ready` 后，在飞书搜这个机器人，发一句「你好」。
4. 机器人会先点一个赞，再弹出思考卡片，最后变成完整回复。卡片上有 **去往网页端**，目标由 `WEB_APP_URL` 决定；默认本机地址通常只能在运行服务的电脑上打开同一条对话。

群测：把机器人拉进测试群。不 @ 它，它不会理。在群主会话发 `@申学助手 用一句话介绍你自己`，回复仍留在群主会话，不会自动创建新话题；如果入站消息本来就在某个话题内，回复才会回到那个话题。

### 完整使用流程

#### 私聊和群聊怎么对应网页上的对话

| 你在飞书里 | 网页上对应 |
| --- | --- |
| 和机器人单聊 | 你的一条「飞书单聊」；同一人始终接着这条，直到 `/new` |
| 群主会话里 @ | 整个群共用一条对话 |
| 已经在某个话题里 @ | 这个话题单独一条，不和群主会话混 |

例子：上午在群里 `@助手 改一版简历摘要`，下午还在群主会话 `@助手 把摘要再缩短`，它还记得上午那轮。如果你点进某个旧话题再 @，那是另一条对话。

#### 常用命令（群里要先 @）

| 命令 | 做什么 |
| --- | --- |
| `/help` | 列出命令 |
| `/new` 或 `/clear` | 新开一条对话，**不删记忆** |
| `/agent` | 弹出「申学助手 / 本地助手」 |
| `/agent 申学` 或 `/agent 本地` | 直接换助手并新开对话 |
| `/stop` | 停当前任务 |
| `/continue` | 发一句「继续刚才的任务。」，相当于新的一轮，不是把上次中断的进程接回去 |
| `/guide 先核对官网` | 用引导模式再开一轮；若上一轮还在跑，会排队，**不会**写进正在跑的那一轮 |

成稿卡片上的 **新对话 / 切换助手 / 重新回复** 和这些命令是同一套。

例子：私聊做完一版 SOP 后发 `/new`，下一句不会再看到刚才的 SOP 正文，但「我偏好先给结论」这类记忆还在。

#### 需要你选择时

助手若要你选方向，飞书弹出橙色卡片 **需要你选择**：上面写完整选项，下面一排竖着的按钮。点一下，卡片变成绿色 **已选择**，助手继续。

例子：`用 AskUserQuestion 问我眼下先推进选校、截止日期、推荐信还是文书`。应看到完整文案，而不是「选校组合与…」。

限制：目前只展示**第一道题、最多 6 个选项**；多选和「其他（自己填）」在飞书上就是点一个按钮。复杂选择请点 **去往网页端**。

#### 发文件、收回文件

把 PDF / Word / 图片发到私聊或 @ 到群里，助手会当附件用。没有配文字时，它会按「请查看附件」开跑。

网页与飞书统一接受不超过 20 MB 的输入文件；进入会话后的用户附件按 SHA-256 校验并作为只读输入，Agent 不能把生成结果写回同一路径。

若机器人缺少资源下载权限、下载失败或文件类型不受支持，飞书会直接提示具体附件没有读到；部分附件成功时，其余附件仍会继续处理。

助手交终稿时，卡片里会出现 **生成的文件**，飞书里还会再发一份文件消息。网页同一助手的工作区 **货架** 里也能找到已呈交的文件。

例子：私聊发简历 PDF，再说「改成一页，不要编造经历」。

#### 协作助手

项目研究员、资料核验员、文书写作和文书审校都是真实运行的协作助手。运行时，飞书卡片会显示当前角色和活动；完成后以主助手的最终回答为准。

旧版“专家往来 / 专家信件”只是内部便签，收件角色不会因此再次执行，现已删除。需要第二轮核验时，主助手必须发起新的真实协作任务，不能用展示性消息代替执行。

现在每次协作都绑定产生它的 Run 和主助手回复。专家结果分为已确认、冲突和待确认；“已确认”若没有有效 HTTP(S) 来源会自动降为待确认。真实 handoff 会把源任务、结构化结果、未解决问题和经过校验的附件清单交给第二个协作助手，再启动一次独立 Query。

飞书成稿只追加简短的“协作核验”人数与计数；遇到重要冲突才显示提醒，不拼接专家全文、本地路径或内部工具输出。完整任务、来源和 handoff 链只在网页对应回复下的“协作与核验”折叠区显示。没有协作时，两端都不渲染空模块。

#### 能力待审卡片

当你把做法做成待审能力时，飞书**最近一次单聊**可能收到橙色 **助手能力有更新**，点 **通过并启用** 或 **拒绝**。群聊收不到这张卡。本机 `http://127.0.0.1:5173` 上，卡片**不会**出现「启用前 / 后回放」按钮（回放链接只在公网 `WEB_APP_URL` 时放出）；请到网页 **工作区 → 能力** 里回放。

#### 每日 / 每周报告

申学助手可以开「每日申请计划」「每周申请回顾」。网页 **定时任务** 里打开后，默认只送到网页。要送到飞书，需要目的地包含 `feishu`，并且你曾经**私聊过**机器人。日报里会带作战卡相对昨天的变化，以及「今天三件事」（取作战卡前三行，不是另做的待办清单）。

作战卡**不会**出现在网页界面上，只喂给模型和飞书日报。

#### 卡片上看不到什么

飞书不显示网页里的 reasoning summary，也不显示私密原始思考；卡片上只有当前活动、正文和完成摘要。飞书卡片也没有「已参考 N 条记忆」。

### 技术细节

- 通道：`FeishuChannel`（`apps/server/src/feishu.ts`）+ `@larksuiteoapi/node-sdk` 长连接；策略 `requireMention: true`，不响应 @所有人。
- 房间键：`p2p:{openId}` / `group:{chatId}` / `group:{chatId}:{rootId}`，存在 SQLite `channel_bindings`。
- 群回复：`replyInThread` 仅当入站消息已在话题里为真，避免每次 @ 开新话题（`feishu-room.ts`）。
- 流式：`channel.stream` 更新同一张 CardKit 卡片；思考 → 活动（尚无正文时）→ 正文；`reasoning.*` 事件忽略。
- AskUser：`AskUserQuestion` → `user.question` → `buildFeishuAskUserCard`；回传只映射第一题。
- 入站附件：允许 `image/*`、PDF、DOCX、XLSX、常见文本；写入 `{workspace}/{conversationId}/attachments/`。
- 出站文件：仅 `presented !== false` 的附件；卡片最多 3 个「打开」按钮，并再发飞书文件消息。
- **去往网页端**：`{WEB_APP_URL}?conversation=`；日报用 `?scheduledRun=`。本地 loopback 也会显示。
- 能力通知 / 定时报告：只查最新 `p2p:%` 绑定，不发群。
- `/guide` 在飞书是 `submit(..., "guide")` 新一轮，不是把文字补进正在跑的 run。
- 事件 handler 必须 3 秒内返回：入站只做去重、点赞、入队。

权限、附件权限与创建应用步骤以 [FEISHU_SETUP.md](./FEISHU_SETUP.md) 为准。

## 自进化

### 它是什么

助手可以学会「以后用同一套做法」，但**不会偷偷生效**。新能力先出现在 **工作区 → 能力** 的 **待确认**，你点 **启用** 之后，以后的对话才会用。

分两种：

- **Skill（技能）**：主助手自己按一份步骤做，例如「改一页简历并导出 PDF」。
- **子代理**：把一块有界的活交给专门的帮手；它不能再转包。

旁边还有 **手册**：几条「要做 / 不要做」的个人偏好，每轮自动塞给模型，不是一个可点的技能。对回答点赞时，可以「记成以后的默认」，写的是手册，不是能力。

官方技能（项目调研、文书写作等）是只读的，自进化**不会改写**它们。

### 完整使用流程

#### 把这一轮的做法收成能力

例子（申学助手，真实 Claude 运行）：

1. 上传简历，说：`把这份简历改成一页 PDF，不要编造经历。`
2. 做完后说：`做成 skill`（或 `做成技能` / `做成子代理` / `交给子代理`）。
3. 活动里出现 **提交待审能力**。助手会说已交到能力页，启用后才生效。
4. 打开 **个人工作区 → 工作区 → 能力**（可先在顶栏选当前助手）。上面 **待确认** 里有一张卡：名称、说明、检查原因，按钮 **启用 / 拒绝 / 预览 / 启用前回放 / 启用后回放**。
5. **预览**看的是原始步骤（Markdown 或 JSON），不是试跑。
6. 点 **启用**。以后新开的对话才带上它。要停用：同一行点 **关闭**。

`做成 skill` 和 `做成子代理` 的差别：前者是技能正文；后者是一份不能再委派的子代理配置。说 `以后都这样` **不会**生成能力。

临时对话不会走这条流程。

#### 网页审和飞书审

- 网页：待确认卡上的启用 / 拒绝。原因记为「工作区确认启用」或「工作区拒绝」。
- 飞书：最近一次**单聊**可能收到 **助手能力有更新**。点 **通过并启用** 或 **拒绝**，同一张卡变成已通过 / 已拒绝。发不出去时，能力仍在网页待确认，原因里会注明飞书未发送。

拒绝后的条目从列表消失，没有「撤销拒绝」。官方能力没有开关。

#### 启用前 / 后回放

回放**不是录像**，也不保证字字相同。它复制那一轮结束时的工作区，按值固定原用户输入与补充、输入附件 Manifest、当时选中的手册条目、申学作战卡、稳定记忆、已启用能力正文，以及当时的学习 session / incident / policy context，再开一条新对话重跑。专家任务会重新真实执行，不复制旧协作记录；学习回放使用独立 `replay` 数据集，不写入 live 策略统计。回放不会因后来修改记忆或能力而偷换对照条件；但运行时模型和外部网页仍可能变化，所以结果不一定完全相同。

| 入口 | 做什么 |
| --- | --- |
| 助手消息上的回放图标 | 回放本轮（当时已启用的能力） |
| 能力页 **启用前回放** | 使用上述已固定内容，不含这条待审能力 |
| 能力页 **启用后回放** | 使用同一份已固定内容，再加上这条待审能力（只在这一轮预览） |
| 飞书卡片链接 | `?replayRun=` / `?replayRun=&withArtifact=`，公网地址才出现按钮 |

例子：待审技能是「一页简历 PDF」。启用前回放应仍按旧办法改；启用后回放应能读到预览技能。新对话标题类似 `回放 · …` / `回放（启用后） · …`。没有快照时会提示还没有可对照的一轮（只有**成功跑完**的一轮会被冻住）。

#### 助手自己也会提议（你仍要启用）

除了你亲口说「做成 skill」：

- 某次任务被判定为「这套做法值得留下」，会先写入手册；类似做法积累几次后，可能自动提交一份待审 **个人工作方法**。
- 定期回顾（大约 7 天或积了足够多自动任务）也可能再提一条待审能力。

这些都还是 **待确认**，不会自动启用。

Demo 模式没有「提交待审能力」工具。回合结束后的启发式只有在手册里已经存在具体步骤时才会生成待审项；没有可复用步骤时不会提交空壳「个人工作方法」。

### 技术细节

- 真相源：SQLite `evolved_artifacts`（`data/agent.db`）。`data/evolved/<profileId>/` 只是**已启用技能**生成的 Claude 本地插件树，不要当 git 源码。
- 提交工具：运行时 MCP `propose_evolved_capability`（`runtime.ts`）。启发式：`EvolutionCoordinator.proposeFromPrompt`，仅当用户文本匹配做成 skill / 子代理。
- 状态：`pending` → `enabled` / `rejected`，之后可 `disabled`。人审路径一律 `holdForHuman`。
- 硬检查（`evolution-evaluator.ts`）：slug、长度、注入句、子代理不得再委派、`maxTurns ≤ 12`、`effort` 必须是受支持的等级、技能/MCP 必须属于该助手。人审**不能**覆盖硬拒绝。
- 领域检查（`domain-evolution-check.ts`）：静态清单（空壳方法、简历须含不编造+交付、截止日期须提官方来源、技能至少两步）。**不是**再开一个 Claude 影子跑。人审启用会跳过这份清单。
- 运行时注入：技能走 Claude `plugins` + `skills`；子代理变成额外 `delegate_*`。能力正文**不**写进 system prompt。手册 / 作战卡 / 记忆走 prompt overlay。
- 回放：完成时拷贝工作区到 `data/workspaces/.snapshots/<runId>/`，并在 `replay_marks` 记录原输入与 overlay 快照。`POST /api/runs/:id/replay`。overlay 快照按值保存手册条目、作战卡、稳定记忆与已启用能力正文；即使当时选中内容为空，回放也不回退到当前能力。启用后回放还会按值加入待审能力正文，只在该回放对话中预览。
- 飞书审卡只发最新 p2p；进程重启后内存里的卡片 id 会丢，旧卡可能无法就地更新。

## 记忆

### 它是什么

跨对话的短事实，不是聊天记录全文。例如「偏好简洁中文」「今年申 2027 秋 CS PhD」。下次开新对话，助手可以接着用，不用你再说一遍。

五类：

| 类别 | 谁能看见 |
| --- | --- |
| 个人资料、偏好 | 两个助手都用（全局） |
| 目标、项目、任务 | 只属于某一个助手 |

目标 / 项目 / 任务**不会**在申学助手和本地助手之间串。网页和飞书是同一份库：飞书申学助手记住的本科院校，网页申学助手也能用。

### 完整使用流程

#### 三种写入方式

**1. 对话里说「记住」**

例子：`记住：以后用简洁中文，先给结论。`

网页会出 toast「已记住：…」，**10 分钟内可撤销**。飞书没有这条 toast，但记忆已经写入。可记个人资料 / 偏好 / 目标 / 项目，不能用这句直接记「任务」。

「忘掉…」需要模型拿到那条记忆的 id，对偏好往往不好使；更稳的是到记忆库里删。

**2. 自己在面板里添加**

**个人工作区 → 记忆 → 添加**。选分类、标题、内容；目标 / 项目 / 任务还要选所属助手。没有 10 分钟撤销。

**3. 回合结束后自动整理**

做完一件实事（不是打招呼），后台可能抽出目标 / 项目，并写一条**任务摘要**。没有「已记住」提示。闲聊、纯问答、「我几岁了」这类不会记成任务。你手写或点「记住」过的条目，自动整理不会覆盖。

例子：`根据清华电子背景，列 2027 秋北美 CS PhD 材料清单。` 结束后到 **记忆 → 任务 / 项目** 里应能看到；对话标题也可能从「新对话」变成更像样的名字。

#### 在面板里管理

打开 **个人工作区 → 记忆**：

- 搜索、按分类筛选。
- **置顶**：排在前面，也保护它不被定期自动精炼改掉。置顶任务**不会**因此每轮都塞进提示词。
- **编辑 / 删除**。删除不可恢复。
- **清空记忆**：只清事实，不清聊天。
- 开关：
  - **使用跨对话记忆**（默认开）：关了则本轮不注入、不能记住/忘记/搜历史；库里的行还在。
  - **自动整理**（默认开）：关了则回合后不再自动写。
  - **参考历史任务**（默认开）：关了则不能检索过去的任务摘要；资料和偏好照样注入。
- **立即整理**：手动跑一轮压缩重复的自动任务。

同一面板还有 **手册 / 能力 / 货架**。货架是已呈交的文件，不是记忆。

#### 对话里的「已参考」

网页回复下有时出现 **已参考 N 条记忆**。那是模型**检索到的历史任务摘要**，点开能跳到当时的对话。

每轮都自动带上的资料 / 偏好**不会**出现在「已参考」里。飞书卡片也没有这项。

例子：第一轮列过材料清单；过几天问「上次清单还缺推荐信吗？」——可能出现已参考。只靠「简洁中文」偏好回答时——没有已参考。

#### 临时对话

网页 **创建对话 → 临时对话**：不写记忆、不进历史，关掉就删。飞书没有临时对话。飞书 `/new` 只换会话，不清记忆。

#### 敏感内容和上限

含密钥、身份证、银行卡、病历、住址等模式的内容会被拒绝写入。标题最长约 80～120 字，正文 2000 字。列表最多 500 条。

#### 作战卡（网页看不到）

申学助手会根据资料 / 目标和看板上的项目，生成一张「申请人作战卡」，塞进模型，并出现在飞书**每日计划**的 diff 里。网页工作区没有这张卡。

### 技术细节

- 存储：`MemoryStore` + SQLite FTS5。`sourceKind`：`auto` / `explicit` / `manual`。界面不展示来源种类。
- 稳定上下文：除 `task` 以外的条目，按置顶 → 重要性 → 更新时间，大约 3000 字 / 20 条，写入 `<user_memory>`。任务只走 `search_past_conversations`，命中后写入 `run_memory_refs`，网页渲染「已参考」。
- Overlay 声明为不可信用户上下文，当前用户输入优先（`overlay-context.ts`）。
- 关记忆时不创建 memory MCP，也不注入 `<user_memory>`；手册和作战卡仍可能注入。
- 自动抽取在 run 完成后排队（最多 3 次）；过短闲聊会跳过，除非像「记住」或「做成 skill」。
- 定期精炼：约 50 条新自动任务或 7 天；不改手动 / 点「记住」/ 置顶的行。
- 改写或重试若替换了原 run，会把那些 run 产生的自动任务标为被替代，检索不再出现。
- 设置是整台实例一份，不是按飞书 / 网页或按助手拆开。多个飞书 allowlist 用户共享同一记忆空间，按单人本机产品使用。

## 三块怎么连在一起

一次典型申学周末：

1. 网页记住「简洁中文、2027 秋 CS PhD」。飞书私聊接着问截止日期——记忆已在。
2. 群里 @ 助手比较两个项目，需要选择时点卡片；点 **去往网页端** 看完整思考和「已参考」。
3. 某一轮改简历的流程很顺，说 `做成 skill`。到 **能力** 里启用前回放对照，再启用。飞书单聊可能同时收到待审卡。
4. 交出去的 PDF 在 **货架**；事实在 **记忆**；步骤在 **手册 / 能力**。`/new` 只换聊天，这三样还在。
